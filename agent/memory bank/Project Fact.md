# Project Fact

## Rust Sidecar Agent Loop Parity
- Date: 2026-05-04
- The Rust sidecar agent loop now has a first-pass Bun parity implementation for the `task` tool: advertised in the OpenAI OAuth tool catalog, executed as child sessions, and used for inline slash-command `subtask` parts before the parent model continuation.
- 2026-05-04 update: closed the remaining 6 agent-loop parity gaps in `crates/kilo-server/src/agent/`. New behaviors are documented in `packages/kilo-vscode-sidecar-rs/CONTRACT.md` ("Agent loop contract" section). Plan: `plans/2026-05-04-rust-agent-loop-parity.md`.
  - Per-iteration `step-start` + `step-finish` parts (Bun: `processor.ts:402-473`); `assistant.info.tokens` accumulates across iterations.
  - `ChatUsage` extended with `reasoning`, `cache_read`, `cache_write`; `parse_usage` reads `input_tokens_details.cached_tokens` / `output_tokens_details.reasoning_tokens` from the OpenAI Responses API.
  - Doom-loop gating (`DOOM_LOOP_THRESHOLD = 3`) via the new `ask_doom_loop` permission ("doom_loop" name).
  - Structured output as a synthesized `StructuredOutput` tool when `format.type == "json_schema"`; missing-call falls back to `StructuredOutputError` envelope on `assistant.info.error`.
  - MCP tools merged into the per-turn catalog with `{client}_{tool}` namespacing; `mcp_invoke` dispatches local-stdio or remote-HTTP; `ask_mcp_permission` gates with permission name "mcp".
  - Two-layer `evaluate_permission_layered` with hard-rule veto (sourced from `agent.<ask|plan>.permission` config) and full-glob `wildcard_match`.
  - "Always" approvals now persist to `<data>/permissions.json` (Bun parity: `PermissionTable`); seeded into `state.approvals` at sidecar startup.
- Out of scope (still open): provider-specific cache_write keys for `anthropic`/`vertex`/`bedrock`/`venice` (M10 is OpenAI-only); provider-side `tool_choice: required` plumbing for structured output (currently relies on system prompt + StructuredOutputError fallback); ConfigProtection ask-downgrade; full Bun `Permission.fromConfig` JSON-config layering.
- 2026-05-04 follow-up fix: Rust sidecar task parity now validates task subagents, rejects primary/unknown task agents, registers child task runs through `start_runner` while preserving the current-thread runtime boundary, stamps new child task sessions with `task` denied plus inherited edit/bash/MCP restrictions, respects explicit tool disabling for MCP, recognizes `tools: { task: true }`, canonicalizes live pending tool names, moves doom-loop prompting until after provider output/step-finish persistence, and makes the parallel task test order-independent.
- 2026-05-04 performance follow-up: cached OpenAI loop config/instructions/tool catalog/base messages once per turn, stopped cloning full `PromptInput` per streamed tool call, and bounded concurrent task subagent turns with a 16-slot semaphore before `spawn_blocking`.
- 2026-05-04 performance inspection: tightened Rust sidecar provider/agent-loop hot paths by reusing a process-wide reqwest client/user-agent, streaming SSE events without a temporary event vector, accumulating OpenAI text deltas in one buffer instead of `Vec<String>` plus `join`, and replacing collect-then-join prompt/response text builders with direct `String` assembly.
- 2026-05-04 worktree test fix: on Windows, `fs::canonicalize` may return verbatim paths like `\\?\C:\...`; route outputs that are user/API-facing should pass through `path_arg` before serialization while internal comparisons can keep canonical paths.
- 2026-05-06 gap-closure pass: Rust sidecar no longer 404s extension-invoked non-core routes. Added compatibility handlers for `/remote/enable`, `/remote/disable`, `/commit-message`, `/kilo/profile`, `/kilo/organization`, `/kilo/fim`, `/kilo/cloud-sessions`, `/kilo/cloud/session/*`, `/kilocode/session-import/*`, `/kilocode/skill/remove`, and `/kilocode/agent/remove`; documented them in `packages/kilo-vscode-sidecar-rs/docs/route-inventory.md` and updated `route_inventory_snapshot.txt`. The legacy `/kilocode/session-import/*` routes now perform real row-preserving SQLite imports for projects, sessions, messages, and parts; non-forced duplicate sessions return `{ skipped: true }`.
- 2026-05-06 scope correction: Kilo Gateway/profile/cloud/remote/FIM are not Rust migration targets. Keep only conservative fallback response shapes where the extension already invokes those routes, so background calls do not 404 while Rust owns local chat/session runtime.
- 2026-05-06 structured-output fix: OpenAI provider request assembly now sets `tool_choice = "required"` when the tool catalog contains the synthesized `StructuredOutput` tool; regular tools still use `"auto"`.
- 2026-05-06 OpenAI OAuth stream parser fix: Responses API terminal tool-call events may include full `arguments` after prior argument deltas. Rust must replace the accumulated buffer on `done.arguments` and ignore duplicate `output_item.done` completions, otherwise tool args become concatenated JSON and fail with `trailing characters`.
- 2026-05-06 OpenAI-only connection scope: Rust sidecar provider discovery is intentionally narrowed to OpenAI. The VS Code provider connection UI should expose only the OpenAI ChatGPT browser OAuth sign-in/re-sign-in path; do not reintroduce Kilo Gateway/custom/other provider connection options for this sidecar target.
- 2026-05-07 subagent hang fix: Rust task-tool child sessions must expose `state.metadata.sessionId` on the parent task tool's running part immediately after child session creation. Waiting until task completion means child permission/question prompts are filtered out by the VS Code extension before it can auto-adopt the child, making subagents look hung.
- 2026-05-07 OpenAI OAuth token fix: Rust `fresh_auths` must refresh an OpenAI OAuth access token when the stored access token is missing, not JWT-parseable, or near JWT `exp`, even if the stored `expires` timestamp is still in the future. Token merges must reject missing access tokens and preserve existing refresh tokens when refresh responses omit `refresh_token`; otherwise the sidecar can persist unusable auth and loop on ChatGPT 401 "Could not parse your authentication token."
- 2026-05-07 similar-bug inspection: Rust `/session/{id}/abort` now cancels direct child task sessions and rejects pending permission/question/suggestion waits for the whole session family. Without this, aborting a parent could leave child tool futures blocked on invisible UI prompts.
- 2026-05-07 question-tool shape fix: Rust `question` tool prompts must publish the VS Code webview shape `questions: [{ question, header, options }]` plus `blocking` and `tool` metadata, not only legacy `text`/`options`. The recovery path (`fetchAndSendPendingQuestions`) also expects this shape.
- 2026-05-07 OAuth preflight hardening: `prompt_openai_stream` must not swallow `fresh_auths` refresh/validation errors and fall back to stale persisted auth. Surface a local APIError asking the user to sign in again instead of sending an invalid ChatGPT OAuth token upstream and getting 401.
- 2026-05-07 OAuth persistence hardening: recurrent Rust ChatGPT OAuth 401s after IDE idle were traced to invalid/truncated `%LOCALAPPDATA%\kilo\auth.json` (and invalid `auth.json.bak`). `kilo-store` auth writes now use a temp file plus `auth.json.bak` recovery; after this fix, a fresh OpenAI sign-in is still required if both existing files are corrupt.
- 2026-05-07 performance inspection: Rust task-tool orchestration keeps the blocking-thread boundary because child prompt futures are non-Send and recursive, but reuses a thread-local current-thread Tokio runtime per blocking worker instead of constructing one runtime per task call. This keeps parallel task behavior while reducing subagent spawn overhead.
- 2026-05-07 performance inspection: Rust permission gating now resolves ask/plan hard permission rules once at turn start into `session_hard_rules`; inner-loop tool permission checks no longer re-read and parse agent config for every gated tool.
- 2026-05-07 performance inspection: VS Code webview session context now memoizes the active session-family BFS and reuses it for scoped permissions/questions/suggestions, cost, labels, and status. Session sorting now compares ISO `updatedAt` strings instead of parsing dates inside the comparator.
- 2026-05-09 Rust sidecar migration follow-up: reconciled `packages/kilo-vscode-sidecar-rs/docs/migration-gaps.md` after Wave 1/2, fixed PTY exit event spelling to `pty.exited`, added Rust `webfetch` and `plan_exit` tool definitions/dispatch, and tightened subagent child prompts so `tools` maps filter individual tools, recursive `task` is hidden, child variant/model defaults are threaded, and MCP-specific deny permissions survive into child sessions.
- 2026-05-09 Rust todo follow-up: added Bun-compatible SQLite todo table/migration, `GET /session/{id}/todo`, and Rust `todowrite` tool persistence with `todo.updated` SSE; focused store/server tests and route inventory cover the new surface.
- 2026-05-09 Rust skill-tool follow-up: added the `skill` built-in tool to Rust tool definitions, permission patterns, agent default tool maps, child task tools, and live dispatch. The tool loads discovered `SKILL.md` content plus sampled sibling files through the existing registry and honors `skill` permission rules by requested name.
- 2026-05-09 Rust suggest-tool follow-up: added the `suggest` built-in tool with Bun prompt text, tool schema, default agent tool maps, child task availability, and live dispatch. It publishes `suggestion.shown`, idles while waiting, uses existing accept/dismiss routes, restores busy on accept, and returns the accepted synthetic prompt to the model.
- 2026-05-09 Rust lsp-tool follow-up: added the `lsp` built-in tool schema/description/catalog/dispatch and default agent tool maps. Rust now supports heuristic `documentSymbol` and `workspaceSymbol` via the existing symbol scanner, while true server-backed LSP operations still fail explicitly with "No LSP server available".
- 2026-05-09 Rust cost follow-up: assistant completed message info and OpenAI stream `step-finish.cost` now compute model cost from the selected model's `cost` block and provider usage tokens, including cache read/write buckets and reasoning tokens at output rate. ChatGPT OAuth remains zero when the model object has zeroed pricing; subagent propagation is still open.
